## Snippet 3 — The density contribution

```csharp
density += restDensity * boundaryVolume * poly6Const * diff * diff * diff;
```


**Explain:**

- The 2023 decoupled-boundary paper warns that naive boundary particles cause density **overestimation**. Given `boundaryVolume = stepX * stepY`, explain when exactly that would happen.

## Snippet 4 — The force, and why the coefficient collapses

```csharp
Vector2 rVec = particles[i].position - boundaryParticles[b];   // inward
float r = Mathf.Sqrt(r2);
Vector2 dir = rVec / r;
float hr = h - r;

particles[i].force += dir * (boundaryVolume * pressure * spikyGradMag * hr * hr);
```

**Explain:**
- Start from Müller's symmetrized form `m_b · (p_i + p_b)/(2ρ_b) · gradW` and show that it reduces to `V_b · p_i · gradW`. State what assumptions about `m_b`, `p_b`, and `ρ_b` you used.
- `p_b = p_i` is called **pressure mirroring**. Why does the boundary using the *fluid particle's own pressure* correctly enforce no-penetration? (Ghost SPH states it as pressure being continuous through the boundary.)
- Why does `dir` point **inward** rather than outward? What would happen visually if it were reversed?
- Note: if `p_i = 0` (clamped), the wall force is also zero. Why is that acceptable now, when it was the cause of the original bug?
