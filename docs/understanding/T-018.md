## Snippet 2 — Pressure is per-particle, force is pairwise

```csharp
private void ComputePressure()
{
    for (int i = 0; i < particles.Length; i++)
    {
        float p = stiffness * (particles[i].density - restDensity);
        if (clampPressurePositive && p < 0f) p = 0f;
        particles[i].pressure = p;
    }
}
```

**Explain:**
- `ComputePressure()` has only one loop and never touches neighbors. `ComputePressureForce()` has a nested neighbor loop. Why the difference? computepressure is for that particle only, whereas force is the effect of particles interacting with each other, thats why we need neighbor loops to compute the force.
- What physical quantity does the nested loop represent that the single loop cannot? one loop would do anything because it only iterate the paricles not their neighbor. to compute the pressure force we need to find out also the pressure emitting from neighboring paricles.

## Snippet 3 — The pressure force itself

```csharp
float spikyGradMag = 30f / (Mathf.PI * Mathf.Pow(h, 5f));

// inside the neighbor loop
Vector2 rVec = particles[i].position - particles[n].position;  // j -> i
float r = rVec.magnitude;
Vector2 dir = rVec / r;
float hr = h - r;

float contribution = particleMass
                     * (particles[i].pressure + particles[n].pressure)
                     / (2f * particles[n].density)
                     * spikyGradMag * hr * hr;

particles[i].force += dir * contribution;
```

**Explain:**
- Why is this force computed from the **gradient of a kernel**, rather than directly from the pressure value? because force is a vector value, thats why we need the gradient to determine the direction of the force applied. 
- Why divide by `particles[n].density` (the **neighbor's** density) rather than `particles[i].density`? because all neighbors presense effecting the pressure. we need to compute the volume of that area that particles effected
- Why does `particleMass` appear at all? Mass is the interpolation weight — it tells the sum how much matter each neighbor represents.

- Explain the `(particles[i].pressure + particles[n].pressure)` term. What would go wrong with just `particles[n].pressure`? (Müller explains this specifically.) its about violation of newton third law, which is reservation of force so sph do this to fix that average the two pressures so both particles use the same number
- `hr * hr` is `(h - r)²`. What is the value of this term at `r = 0`, and at `r = h`? Why does each matter? `r = 0` non-zero → prevents overlap and`r = h` zero → prevents jolts when particles enter/leave the neighbourhood

## Snippet 4 — The sign (the part that is easy to get backwards)

```csharp
Vector2 rVec = particles[i].position - particles[n].position;  // points j -> i
Vector2 dir = rVec / r;
particles[i].force += dir * contribution;
```

**Explain:**
- Derive it yourself: the kernel gradient is `∇W = (dW/dr) · (r_i − r_j)/r`. For the Spiky kernel, is `dW/dr` positive or negative? negative — the kernel shrinks as r grows toward h, so the slope is always negative.
- Given `f_i = −Σ m (p_i + p_j)/(2ρ_j) ∇W`, and positive pressure, which direction must `f_i` point — toward or away from `j`? `∇W` points from i toward j. But the formula has a leading minus sign, so `f_i = −(positive) × (pointing at j)` = pointing away from j. Answer: **away from j — repulsive**.
- So why is `dir` defined as `position[i] - position[n]` and used with a **positive** sign, instead of `position[n] - position[i]` with a negative sign? Because `position[i] - position[n]` already points away from j, which is the direction `f_i` needs. And `spikyGradMag` is already the positive magnitude — the negative sign of `dW/dr` was folded into the direction. The alternative form with two sign flips produces the same vector; it is the same algebra with the signs pre-cancelled.
- What would happen visually if this sign were flipped? Positive pressure would **attract** instead of repel. Compressed regions would pull particles together into dense clumps, and sparse regions would blow apart. This is exactly the bug we hit — compressed particles sticking and stacking instead of spreading.

## Snippet 5 — Clamping the equation of state

```csharp
float p = stiffness * (particles[i].density - restDensity);
if (clampPressurePositive && p < 0f) p = 0f;
```

**Explain:**
- What behavior does clamping remove? It removes **negative pressure** — the tension (pulling) side of the equation of state. Unclamped, any under-dense region gets `p < 0`, which pulls particles together. Clamping forces `p ≥ 0`, so the fluid can only push.
- With clamping on, the pressure force is one-directional. Why does that mean the fluid **cannot** reach a true equilibrium? Equilibrium needs errors corrected in **both** directions. Too dense is corrected (push apart), but too sparse is not (nothing happens). So there is no density value the fluid returns to — it can only expand until pressure switches off, then coast. That is absence of force, not a balance point.
- What is the trade-off of turning clamping off? You gain a true two-way restoring force, so the fluid can reach equilibrium, hold its shape, and behave cohesively. You lose **stability**: negative pressure brings back sticking and stringing at free surfaces and walls (where density is under-estimated), and the **tensile instability** — a documented SPH failure where negative pressure causes particles to cluster (Monaghan 2000).

## Snippet 6 — Forces become motion

```csharp
Vector2 acceleration = particles[i].force / particles[i].density + gravity;
particles[i].velocity += acceleration * dt;
particles[i].position += particles[i].velocity * dt;
```

**Explain:**
- Why divide `force` by `density` to get acceleration? What are the units? force here is per-unit-volume, so dividing by density converts it to per-unit-mass — which is acceleration. Units: m/s².
- Why is gravity **added** here instead of being accumulated into `force` like the pressure force? Gravity is already an acceleration (m/s²). To store it in force you would first have to multiply by density (ρ·g) to convert it into a force density, then divide by density again to get back to acceleration.Adding it directly to the acceleration skips that round trip. It is mathematically identical but simpler, and it does not require density at all.
- The pressure force is conservative. Why does that mean the fluid will keep sloshing forever without an extra term? The pressure force is −∇p, derived from the fluid's internal energy. Like a spring, it stores and releases energy but never destroys it. So a fluid driven only by pressure will slosh forever. To settle, the system needs something that turns kinetic energy into heat. In SPH, that is viscosity
