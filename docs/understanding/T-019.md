## Snippet 1 — A structural change: the reset moved out

Before T-019, `ComputePressureForce()` zeroed the accumulator itself:

```csharp
for (int i = 0; i < particles.Length; i++)
{
    particles[i].force = Vector2.zero;   // ← used to live here
    for (int j = 0; ...) { ... }
}
```

Now there is a separate pass:

```csharp
private void ResetForces()
{
    for (int i = 0; i < particles.Length; i++)
    {
        particles[i].force = Vector2.zero;
    }
}
```

```csharp
ResetForces();            // zero once
ComputePressureForce();   // add pressure
ComputeViscosityForce();  // add viscosity
```

**Explain:**
- Why did the reset **have** to move out of `ComputePressureForce()` once viscosity was added? What would go wrong if it stayed inside?
- In T-018 you were asked whether a separate reset loop was correct. Why was it *optional* then but *required* now?

## Snippet 2 — The viscosity force

```csharp
viscForce += viscosity
             * particleMass
             * (particles[n].velocity - particles[i].velocity)
             / particles[n].density
             * viscLapMag * (h - r);
```

**Explain:**
- Why `(v_j − v_i)` and not just `v_j`? Müller justifies this with a frame-of-reference argument — what is it?
- Notice there is **no direction vector** here, unlike the pressure force which needed `dir`. Where does the direction come from instead, and why does that make this force harder to get backwards?
- Why divide by `particles[n].density` (the neighbour's density)?
- What role does `particleMass` play?

## Snippet 3 — Why viscosity needs its own kernel

```csharp
float viscLapMag = 40f / (Mathf.PI * Mathf.Pow(h, 5f));   // 2D
```

```csharp
∇²W_visc(r, h) = 40/(πh⁵) · (h − r)
```

**Explain:**
- Why can't Poly6 or Spiky be used for viscosity? Müller describes a specific failure — what is it?
- The Laplacian of the viscosity kernel is **positive everywhere** for `0 ≤ r ≤ h`. Why does that guarantee the force only ever *reduces* velocity differences?
- What happens to the simulation's energy if `∇²W` is allowed to go negative for close particles?
- The quadratic term `(h − r)²` appears in the pressure force, but the viscosity term is linear `(h − r)`. Why doesn't `(h−r)²` appear here?

## Snippet 5 — What viscosity actually does to the solver

```csharp
ResetForces();
ComputePressureForce();   // conservative — stores and releases energy
ComputeViscosityForce();  // dissipative — destroys energy
Integrate(dt);
```

**Explain:**
- In T-018 you listed three prerequisites for a stable equilibrium. Which one does viscosity satisfy?
- Why can the fluid never settle no matter how correct the pressure force is, without this term?
- Why is this term sometimes called **artificial** viscosity rather than physical viscosity?
- `viscosity = 50` was chosen by estimating a decay time from the particle scale. Why must `μ` be re-tuned whenever you change `restDensity`, `particleMass`, or `smoothingLength`?
