## Snippet 2 — Density computation

```csharp
private void ComputeDensity()
{
    for (int i = 0; i < particles.Length; i++)
    {
        float density = 0f;

        for (int j = 0; j < neighbors[i].Count; j++)
        {
            int neighborIndex = neighbors[i][j];
            float r = Vector2.Distance(particles[i].position, particles[neighborIndex].position);

            if (r < smoothingLength && r > 0f)
            {
                float diff = smoothingLength * smoothingLength - r * r;
                density += particleMass * (4f / (Mathf.PI * Mathf.Pow(smoothingLength, 8f))) * Mathf.Pow(diff, 3f);
            }
        }

        particles[i].density = density;
    }
}
```

**Explain:**
- Why do we loop over `neighbors[i]` instead of all particles? neighbor search already identified which particles are within range, so we loop only those instead of checking all N particles again. It turns an O(N²) all-pairs check into an O(N) neighbor loop.
- What does `r` represent, and why is the `r < smoothingLength` check already guaranteed by neighbor search? r is distance of the particle to neigbor particle. r guaranteed less than smoothingLength because its alreayd list as neighbors, whcih means its obviously inside the smoothingLength.
- What does the Poly6 term compute conceptually? conceptually the poly6 computer field around a particle that are matter, which is neigbors that inside the smoothingLength. to approximate area surrounding the aprticle
- Where does the result go, and why is it stored per-particle? the result go to the particle, because the result if for that specific particle based on its neighbors. why is it per particle because in sph, every partice have their own mass, velocity and accerelearating.

## Later amendment (after T-024)

**The density kernel is no longer Poly6.** It is now **SpikyPow2**, `6/(πh⁴)·(h−r)²`.

Why: the pressure model was extended to a two-channel scheme (see the near-pressure
supplement). Each channel's force is the gradient of its own density kernel, and the
near channel needed a sharper kernel than the main one. Poly6 has no counterpart in
that pairing, so it was retired from density.

Poly6 has not disappeared — it now serves as the **viscosity weight** instead, where
its non-negativity is the property that matters.

Everything else in this note still holds: the density is a weighted sum over
neighbours within `h`; particles in crowded regions read high density; `restDensity`
is still the target; and `CalibrateParticleMass()` still scales mass so the spawn's
mean density lands on `restDensity × spawnCompression`. The calibration measures
whatever kernel is in use, so it absorbed this change automatically.
